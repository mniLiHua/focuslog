## v3.0.0 正式版 —— 作者 冰叁狼

**3.0 = 产品形态换代**：从"一堆 bat + 命令行"到"网页为唯一操作入口"——
看数据、改分类、开关自启/提醒、每周自动备份、一键体检、搬家导入，全部在浏览器里完成；
目录全中文（专注记录/工具/焦点监控），分发零 md（微信直接传包）。

### v3.0.0 新增
- **每周自动备份**：记录进程跨天时检查，到期自动 zip 到指定目录（目录/间隔在
  面板 → 系统设置里配置，保留最近 10 份）；手动「立即备份」不变
- **「关于」页**：版本、作者、数据目录、已记录天数、常见问题速查

### 换代包含（v2.8 → v2.15.1 累计）
时间面板（双主题/趋势/热力/排行聚合分页/番茄钟/体检）· 网页承载全部操作
（分类助手/管理/导入旧数据/系统设置/周报/CSV）· 导出产物弹出资源管理器 ·
目录中文化 · 双实例运行时自检 + 旧副本扫描 · parse_log 文件级缓存（8.4s→0.06s）·
首次运行向导 · 一键迁移（拖放/自动搜索）· 发布链路（检查面板/打包/更新）

## v2.11.1（当前）
- 修：**开机自启场景不触发自动维护**。原来维护只挂在「运行中发现跨天」，
  而自启动是「昨天关掉、今早启动」——走的是启动时的另一段代码。
  现在抽成公共函数 `run_daily_maintenance()`，两条路径都调用。
  （实测：模拟该场景 → 日志出现 `[MAINTAIN]|跨天自动维护完成`）
- 修：GUI exe 下 `sys.stdout` 是 `None`，`summary.py` 顶部的编码兼容代码直接
  `AttributeError: 'NoneType' object has no attribute 'buffer'` ⇒ 维护静默失败。
  tracker 侧先兜底再 import，summary 侧改防御式判断
- 修：维护失败原来被 `except: pass` 吞掉 ⇒ 现在写 `[MAINTAIN-FAIL]|异常类型: 信息` 留痕
- 修：趋势条不跟随范围（选了「近 7 天」仍画全部 55 天）⇒ 趋势窗口跟着范围走，
  今日/近 7 天画 7 根、近 30 天画 30 根、全部才画全历史
