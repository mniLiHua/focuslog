# 开发与经验（FocusLog 内部规范）

> 给未来的自己/协作者：这个项目的结构约定、发布流程、以及踩过的坑。

## 结构约定

- **仓库根 = 运行目录**：入口 bat 全放根目录（普通用户只看得到这些），
  `焦点监控/`、`专注记录/` 只放程序与数据；数据一律 `.gitignore` 挡住。
- **共享模块**：`焦点监控/category_utils.py`（分类规则）、`archive_utils.py`（归档）、
  `专注记录/summary.py`（解析与统计）、`dashboard.py`（看板数据）。**同一件事只写一处**，
  面板/服务/守护程序全部复用，别在模板里另算一遍。
- **口径单一来源**：范围/周/月/日的汇总结构都是 `{f,t,cats,apps,win}`，
  前端只切换显示。

## 发布流程

1. 改完先 `python tests\selftest.py`（兼容性 14 项）
2. `build.bat` 重打包三个 exe（**改了 .py 不重打包 = 跑的还是旧版**）
3. `打包发布.bat` 出 zip（内含两道防泄漏断言：不得有真实日志、category.txt 先剔私人条目）
4. `git commit` + `git tag -a vX.Y.Z` + `git push --follow-tags`（tag 是回滚锚点）

版本语义：修 bug / 小工具 = 补丁位；**新增子系统**（如面板服务、周报）= 中间位加一。

## 踩过的坑（改代码前先读一遍）

**打包**
- 跨目录模块必须显式 `--paths` + `--hidden-import`，否则 exe 里 `ModuleNotFoundError`
- onefile 的 `__file__` 指向 `%TEMP%\_MEIxxx` ⇒ 数据目录要用 `sys.frozen` 判断取 exe 位置
- GUI（`--noconsole`）下 `sys.stdout/stderr` 是 **None**，被调模块顶部若做
  `sys.stdout.reconfigure` 会直接崩 ⇒ 调用前先兜 `io.StringIO()`

**编码**
- `*.bat` 必须存 **GBK**（cmd 按代码页读；UTF-8 中文会变乱码，连路径都找不到）
- `.ps1` 同理按 ANSI 读 ⇒ 别在 PowerShell 脚本里写中文
- Python 脚本里输出中文到 GBK 控制台会 `UnicodeEncodeError` ⇒ `sys.stdout.reconfigure(errors="replace")`

**本地服务**
- 路由要抽一个 GET/POST 共用入口（本项目曾把新接口全挂在 `do_GET`，POST 一律 404）
- 写文件类接口都要 try/except 返回 JSON 错误，不要让它把连接直接掐掉

**数据**
- 改 `category.txt` 必须：先备份 `.bak`、原子替换、**保留分类上方的说明注释**、写回**幂等**
  （曾因头部注释提取把分隔注释也吞进去，写一次叠一层）
- 清测试产物要用"前后快照对比"，别用文件名前缀猜（曾误删一天的深耕记录）

**自动化**
- 跨天维护有**两条**触发路径：① 进程一直开着跨零点 ② **开机自启**（昨天关、今早开）。
  少挂一条 = 最常见的场景不触发（本项目 v2.11.1 才补上）
- 后台任务失败必须**留痕**（写 `[MAINTAIN-FAIL]|异常信息`），
  `except: pass` 会让"到底跑没跑"永远说不清

## 关键配置

| 文件 | 作用 |
|---|---|
| `专注记录/category.txt` | 分类规则（行序 = 优先级；支持 `proc=`/`进程=`、`title=`/`关键词=`、`*` 通配） |
| `专注记录/goals.json` | 每日专注目标 + 单应用上限（分钟），改完一分钟内生效 |
| `专注记录/focus_state.json` | 当日累计（别手改） |
| `VERSION.txt` | 版本单一来源 |
